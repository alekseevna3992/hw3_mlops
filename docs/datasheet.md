# Datasheet: IT Support Assistant (v1 / v2)

## Источник

Датасет синтезирован **собственным детерминированным генератором** `src/collect.py`. Сторонние источники не использовались: ни HuggingFace, ни выгрузок StackExchange, ни чужого кода.

Генератор опирается на 20 шаблонов вопросов по 11 темам IT-поддержки:

- Windows (8 вопросов)
- Linux (8)
- macOS (6)
- Git (8)
- Python (8)
- VS Code (6)
- Docker (8)
- Terminal (6)
- Node.js (6)
- Networking (6)
- Development Environments (6)

Вопросы оборачиваются 24 детерминированными парафразами (`make_question`), ответы — 12 дополнениями (`make_answer`) поверх 22 базовых ответов. Роли фиксированы: system / user / assistant. Системных промптов — 5 вариантов.

**Лицензия.** Собственная генерация, ограничений на использование нет. Код генератора — в репозитории.

## Распределение длин (v1, после clean)

- user: p50 = 121 симв., p90 = 147, p99 = 170, max = 184;
- assistant: p10 = 256, p50 = 436, p90 = 702, max = 759;
- p90/p10 для assistant = 2.74 (порог ≥ 1.6);
- CV длин assistant = 0.342;
- доля самой частой длины assistant = 1.17% (порог ≤ 25%);
- доля ответов-дублей = 0% (порог ≤ 30%).

## Как устроен сплит

- Ключ группы — `normalize_group(topic)`. Группа = «тема / сценарий», например `git / troubleshooting scenario 3`.
- Перемешиваются **группы** (`random.Random(42).shuffle(keys)`), затем группы целиком распределяются по сплитам в пропорции 0.8 / 0.1 / 0.1.
- Фактические доли v1: train 0.8144, val 0.1001, test 0.0855.
- Фактические размеры v1: train 838 (61 группа), val 103 (8), test 88 (7).
- Проверка контаминации train/test: `id_overlap: 0`, `text_overlap: 0`, `group_overlap: 0`, `near_dup_pairs: 0`.

## Что датасет не покрывает

- **Реальный шум пользовательских формулировок.** Вопросы — детерминированные парафразы одной базы; орфографических ошибок, склеенных сообщений, «а ещё вот это не работает» нет.
- **Многошаговый диалог.** В каждом примере ровно одна пара user/assistant. Модель не увидит уточнений и follow-up.
- **Реальные логи и вывод команд.** Ассистент ссылается на типичные команды (`top`, `df -h`, `docker logs`), но конкретных выводов и текстов ошибок в датасете нет.
- **Длинный хвост тем.** 11 тем × несколько сценариев — это типовые проблемы, не редкие инциденты.
- **Русскоязычные запросы.** Весь корпус на английском.
- **Отдельный раздел про безопасность.** Риски (удаление файлов, обход UAC, `rm -rf /`) не выделены — только общая оговорка «avoid destructive actions» в одном из системных промптов.

## Осознанные отклонения от дефолтных порогов

- **`min_answer_len_ratio = 1.6`** оставлен. Покрывается фактическим p90/p10 = 2.74 за счёт трёх «стилевых» классов ответа: короткий (base + уникальная метка), длинный (base + стандартный блок диагностики + метка), средний (base + контекст `make_answer` + метка).
- **`max_duplicate_answer_share = 0.30`** оставлен. Фактическое значение — 0.0, потому что к каждому ответу добавляется уникальный детерминированный хвост `(case <hex>)`.
- **`min_groups = 50`, `max_group_share = 0.10`** оставлены. 76 групп при крупнейшей 1.75% дают большой запас.

## Использование

- Формат: JSONL, одна строка = один пример. Поля: `id`, `topic`, `messages` (ровно три роли в порядке system → user → assistant).
- Версионируется DVC; remote — локальная папка `../dvc_remote`.
- Две версии: `make v1` / `make v2`. Разница — через `make diff` (`dvc metrics diff`).
